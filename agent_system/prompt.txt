了解：偵測器與攻擊模擬器是「不同的 EXE（不同進程）」。

因此你目前的所有 VirtualQuery / ReadProcessMemory 只掃到「偵測器自己的位址空間」，永遠不會看到攻擊模擬器分配的那些 0x000001D0B7xx0000 區域。

要真正檢出攻擊，需要“跨進程”版本：用 VirtualQueryEx(targetHandle, …) + ReadProcessMemory(targetHandle, …)，並且針對「被監控的每個 PID」排程掃描事件。下面給你完整改造步驟與 Patch 範本。

================================================== A. 根本問題回顧
目前 MEMORY_REGION_SCAN 事件只帶「偵測器自己的 PID」，scan_memory_for_attacks() 只 VirtualQuery(本進程)。
exec_page_tracker 以 base address 為 key，不含 PID。跨進程後會混淆。
schedule_periodic_scan 沒為每個 monitored process 單獨建立掃描事件。
check_executable_integrity / check_heap_region 仍用 get_process_handle(ev.process_id)，但事件的 process_id 都是偵測器本身，所以拿不到攻擊進程的頁面。
你尚未把攻擊模擬器 PID 加入 memory_monitor_->monitored list（或加了但掃描流程沒用它）。
================================================== B. 改造目標
支援多進程：每個被監控 PID 定期發 MEMORY_REGION_SCAN。
掃描函式改成 scan_process_memory(pid, hProcess)。
exec page tracking 分 PID：key=(pid,pageBase)。
Synthetic MEM_PROTECT_CHANGE 事件要綁定正確 pid。
Integrity / Heap 檢查事件必須保留對應 pid。
可以動態新增攻擊模擬器（例如藉由名稱 match 或手動指定 pid）。
================================================== C. 新 / 調整資料結構

================================================== D. 事件流程變更
schedule_periodic_scan():

不再用 GetCurrentProcessId()。
迴圈 memory_monitor_->get_monitored_processes()。
每個產生 Event::MEMORY_REGION_SCAN，填 ev.process_id = p.process_id, ev.process_handle = p.process_handle。
handle_memory_region_scan_event(ev): 呼叫 scan_process_memory(ev.process_id, ev.process_handle)。

scan_process_memory():

用 VirtualQueryEx(hProcess, address, &mbi,…)。
產生 EXECUTABLE_INTEGRITY_CHECK / HEAP_REGION_CHECK 時保留 ev.process_id。
exec_page_tracker 使用 ExecKey(pid, base)。
Synthetic MEM_PROTECT_CHANGE 事件：process_id = 目標 pid。

check_heap_region / check_executable_integrity：不要用 GetCurrentProcess() 讀自己，要用對應 pid 的 handle（從 get_process_handle(pid) 取得）。

----- 修改 schedule_periodic_scan() -----
void EventHandler::schedule_periodic_scan() {
if (!memory_monitor_) return;
auto processes = memory_monitor_->get_monitored_processes();
for (auto const& p : processes) {
if (p.process_handle == INVALID_HANDLE_VALUE) continue;
Event ev;
ev.type = Event::Type::MEMORY_REGION_SCAN;
ev.process_id = p.process_id;
ev.process_handle = p.process_handle;
ev.timestamp_ms = EventUtils::now_ms();
ev.meta = "Periodic memory scan pid=" + std::to_string(p.process_id);
ev.priority = EventPriority::NORMAL;
enqueue_event(ev);
}
}

----- 修改 handle_memory_region_scan_event -----
void EventHandler::handle_memory_region_scan_event(const Event& ev) {
if (ev.process_handle && ev.process_handle != INVALID_HANDLE_VALUE) {
scan_process_memory(ev.process_id, ev.process_handle);
}
}

----- 新增 scan_process_memory (取代 scan_memory_for_attacks 的用途) -----
void EventHandler::scan_process_memory(DWORD pid, HANDLE hProcess) {
MemoryDetectionEngine::log_message("DEBUG",
"*** SCAN_PROCESS_MEMORY pid=" + std::to_string(pid) + " ***");
LPVOID address = 0;
MEMORY_BASIC_INFORMATION mbi;
int scanned = 0;
while (VirtualQueryEx(hProcess, address, &mbi, sizeof(mbi)) &&
(max_regions_to_scan_ <=0 || scanned < max_regions_to_scan_)) {

複製
    if (mbi.State == MEM_COMMIT) {
        bool is_exec = is_executable_protect(mbi.Protect);

        // exec integrity
        if (is_exec) {
            Event ex;
            ex.type = Event::Type::EXECUTABLE_INTEGRITY_CHECK;
            ex.process_id = pid;
            ex.process_handle = hProcess;
            ex.address = (uint64_t)mbi.BaseAddress;
            ex.size = mbi.RegionSize;
            ex.timestamp_ms = EventUtils::now_ms();
            ex.meta = "Exec integrity scan";
            enqueue_event(ex);
        }

        // heap-like
        if ( (mbi.Type == MEM_PRIVATE || mbi.Type == MEM_MAPPED) &&
             (mbi.Protect & (PAGE_READWRITE | PAGE_EXECUTE_READWRITE | PAGE_READONLY | PAGE_WRITECOPY | PAGE_EXECUTE_WRITECOPY))) {
            Event hv;
            hv.type = Event::Type::HEAP_REGION_CHECK;
            hv.process_id = pid;
            hv.process_handle = hProcess;
            hv.address = (uint64_t)mbi.BaseAddress;
            hv.size = mbi.RegionSize;
            hv.timestamp_ms = EventUtils::now_ms();
            hv.meta = "Heap region scan";
            enqueue_event(hv);
        }

        // exec page tracker
        ExecKey ek{pid,(uint64_t)mbi.BaseAddress};
        {
            std::lock_guard<std::mutex> lk(exec_pages_mutex_);
            auto& info = exec_pages_[ek];
            bool was_init = (info.first_seen_ts != 0);
            if (!was_init) {
                info.first_seen_ts = EventUtils::now_ms();
                info.last_protect = mbi.Protect;
                info.seen_exec = is_exec;
                if (is_exec && mbi.Type == MEM_PRIVATE) {
                    Event sp;
                    sp.type = Event::Type::MEM_PROTECT_CHANGE;
                    sp.process_id = pid;
                    sp.process_handle = hProcess;
                    sp.address = (uint64_t)mbi.BaseAddress;
                    sp.size = mbi.RegionSize;
                    sp.timestamp_ms = info.first_seen_ts;
                    sp.meta = "Synthetic EXEC(initial)";
                    sp.priority = EventPriority::HIGH;
                    sp.source = EventSource::DERIVED;
                    enqueue_event(sp);
                }
            } else {
                if (info.last_protect != mbi.Protect) {
                    bool was_exec = is_executable_protect(info.last_protect);
                    if (!was_exec && is_exec) {
                        Event sp;
                        sp.type = Event::Type::MEM_PROTECT_CHANGE;
                        sp.process_id = pid;
                        sp.process_handle = hProcess;
                        sp.address = (uint64_t)mbi.BaseAddress;
                        sp.size = mbi.RegionSize;
                        sp.timestamp_ms = EventUtils::now_ms();
                        sp.meta = "RW->EXEC transition";
                        sp.priority = EventPriority::HIGH;
                        sp.source = EventSource::DERIVED;
                        enqueue_event(sp);
                    }
                    info.last_protect = mbi.Protect;
                }
            }
        }
        scanned++;
    }
    address = (LPVOID)((uintptr_t)mbi.BaseAddress + mbi.RegionSize);
    if (address < mbi.BaseAddress) break;
}
MemoryDetectionEngine::log_message("DEBUG",
    "*** SCAN_PROCESS_MEMORY pid=" + std::to_string(pid) + " regions=" + std::to_string(scanned) + " ***");
}

================================================== F. memory_monitor 加入攻擊模擬器
枚舉進程，用 Toolhelp32 或 EnumProcesses。
比對 exe 名稱（例：attack_simulator.exe）。
為它建立 ProcessInfo{pid, OpenProcess(PROCESS_QUERY_INFORMATION|PROCESS_VM_READ, FALSE,pid), category=ATTACK_SIMULATOR}。
放進 internal vector。
get_monitored_processes() 回傳時包含它。
若你已經有 MemoryMonitor 類別，只需確保它真的包含那個 PID，啟動後 log 一次列表：

}

================================================== G. 測試流程建議
啟動偵測器：看 log 是否列出 [MON] pid=攻擊模擬器PID。
等第一輪 schedule_periodic_scan → 應看到對該 PID 的 MEMORY_REGION_SCAN dispatch。
出現：*** SCAN_PROCESS_MEMORY pid=xxxx ***
產生 MEM_PROTECT_CHANGE / EXECUTABLE_INTEGRITY_CHECK 自然帶 pid=xxxx。
之後啟動攻擊功能（ROP、Realistic），再次掃描應出現 Synthetic 或 RW->EXEC transition（如果你的掃描頻率覆蓋到 RW 階段）。
IntegrityCheck log 中 ret_cnt / pop_cnt > 閾值 → 產生 ROP/Shellcode Indicators。
如果掃描頻率太低導致總是只看到“初始就是 EXEC”，仍然可以：

對 VirtualAlloc 掛 Hook（或在攻擊模擬器加入共享 channel，將新分配地址傳到偵測器 → 偵測器針對那些地址優先 VirtualQueryEx）。
或縮短 scan_interval_，僅對 ATTACK_SIMULATOR 類別使用更高頻率。
================================================== H. 取得更即時的 RW->RX 轉換（進階）
(不一定現在做)

DLL 注入攻擊模擬器，Hook VirtualProtect / VirtualAlloc / WriteProcessMemory → 將事件 (pid, base, size, oldProtect,newProtect) 經 NamedPipe/共享記憶體傳回偵測器。
偵測器收到後立即建立 MEM_PROTECT_CHANGE + EXECUTABLE_INTEGRITY_CHECK 而不用等掃描。
替代方案：ETW (Microsoft-Windows-Threat-Intelligence 或 VirtualAlloc Trace)，或內核驅動。
================================================== I. 常見陷阱
權限不足：必須以與目標同位元數 (64-bit -> 64-bit)；32-bit 偵測器讀 64-bit 進程會失敗。
句柄失效：進程結束後 cache 未清理 → 你已有 cleanup，但要記得在 get_process_handle 補 failing log。
Region 巨大 (MEM_IMAGE) → 讀取 4KB / 8KB 片段即可，不要整段讀。
讀失敗 GetLastError = 299 (ERROR_PARTIAL_COPY) → 對含 guard/NOACCESS 子頁面要縮減讀取長度。
max_regions_to_scan_ 過小 → 高位址區域永遠不到。建議跨進程模式下預設 -1（不限制）或分階段（先前 4096 region，然後記錄未掃描游標）。
